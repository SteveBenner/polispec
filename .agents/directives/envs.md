## What each environment forbids

### dev

- deny R-XENV-COPY: data.copy — data class not allowed in destination environment
- warn R-POLICY: policy.edit — policy files take effect only after promotion to stable
- warn R-DEV-REWRITE: git.rewrite — main is shared history

### test

- deny R-XENV-COPY: data.copy — data class not allowed in destination environment
- deny R-TEST-DIRECT: git.push, git.merge, git.commit, git.tag — test moves only through `polispec promote --to test`
- deny R-TEST-REWRITE: git.rewrite — test history is never rewritten
- allow R-TEST-PROMOTE: promote — -
- allow R-TEST-OPS: deploy, service.control, data.write, fs.write — -
- warn R-POLICY: policy.edit — policy files take effect only after promotion to stable

### prod

- deny R-PROD-GIT: git.commit, git.push, git.tag, git.merge, git.rewrite, git.branch, release.publish — the production branch moves only through `polispec promote --to stable`, run by the operator
- deny R-PROD-SVC: service.control, service.config, deploy, promote — live services change only through the operator
- deny R-PROD-FS: fs.write — the production checkout is not edited by agents
- warn R-PROD-DATA: data.write — live user data
- deny R-PROD-SECRET: secrets.read — production secrets are not readable by agents
- deny R-XENV-COPY: data.copy — data class not allowed in destination environment
- warn R-POLICY: policy.edit — policy files take effect only after promotion to stable

## Promotion

- to test: from `main`, by agent or operator, gates G-CLEAN, G-VHOMES
- to stable: from `test`, by operator, gates G-TESTED, G-FREEZE

Only the operator runs `polispec promote polispec --to stable`.

## Operators and rollback

- test: operators agent, operator
- prod: operators operator; rollback `polispec deploy polispec stable --tag vPREV`
