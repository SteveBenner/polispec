# AGENTS.md: polispec

[ENVS] when developing this repo: it serves real users; dev is `main`, test is `test`, prod is `stable`; run `polispec resolve .` before writing and obey its verdict; table in .agents/directives/envs.md   d/ENVS   ⚙ guard:polispec   ⚡ [always]

polispec is a plugin built on rplugin, the SDK for agent-harness plugins, and
installs and runs without it.
`CLAUDE.md` links to this file, so every harness reads the same text.

## Using it for someone

- Install it without rplugin with `install.sh`, or from a clone with
  `bin/polispec pin` then `polispec install --harness claude|codex`, or as a
  Claude Code or Codex plugin; `README.md` lists every path. On a host that has
  rplugin, it is installed with `~/.rplugin/bin/rplugin install polispec` and
  checked with `~/.rplugin/bin/rplugin doctor polispec`, which must report zero
  findings; read rplugin's own `~/.rplugin/AGENTS.md` for that path.
- What polispec does and its settings (`polispec.enforce`, `polispec.ledger`,
  `polispec.operator` and `polispec.code.specs_repo`, changed with
  `polispec settings set`, or `rplugin settings` on an rplugin host) are
  described in `README.md`; the contract is `specs/app.yml`.
- Its skill is `skills/polispec/SKILL.md`; its command, when installed, is `polispec`
  on the user's `PATH`.
- If it owns a corpus, rplugin created it for the plugin. Read and write it
  only through the plugin or `rcorpus`, never by editing its files.

## Stewardship: working on polispec itself

Read `rules/polispec-stewardship.md` before developing, installing, upgrading or
repairing polispec, applying a package, or changing a project's specs, the
global shelf or the ledger. In short:

- The running polispec is the live guard for every agent on the host. Check
  what runs with `polispec doctor` (`runtime: pinned|clone|sealed|unknown`).
  Never edit the running copy; a clone runtime warns on every write into it and
  a pinned one denies (`R-POLISPEC-RUNTIME`).
- Build every change in a separate git worktree, verify it with that tree's
  `bin/polispec` against scratch `POLISPEC_LEDGER`, `POLISPEC_HOME`,
  `POLISPEC_GLOBAL` and `POLISPEC_STATE_HOME` (never redirect `XDG_STATE_HOME`),
  run `bin/polispec smoke run --against <installed release>`, then merge, tag and
  reinstall with `rplugin install <repo> --ref <tag>`, or `polispec pin --ref
  <tag>` on a host without rplugin. On a host that is not
  pinned yet, merge only verified code, as one fast-forward.
- Rulebook changes go through `polispec plan` and `polispec apply`. Loosening,
  mixed and global plans, status flips and enforce-mode changes need the user's
  yes before `apply --confirm <plan-id>`.
- `polispec steward --check` reports whether the host is protected;
  `polispec steward` (or `apply --with-stewardship`) makes sure the installed
  polispec ships this rule, checks the runtime protection and pins the runtime before it
  applies anything.

## Changing it

- The manifest is `polispec.rplugin.yml` (schema `rplugin/v1`,
  `~/.rplugin/specs/plugin.yml`). `VERSION`, the manifest's `version` and
  `.codex-plugin/plugin.json` must agree.
- Code uses every capability (secrets, events, state, registry, schedule,
  corpus) through `Rplugin::Ports.for("polispec", root: <plugin root>)`. Never
  call a host's service or read its files directly, and never copy rplugin's
  runtime or catalogue into this plugin.
- Before calling a change done, run `rplugin check polispec`, `rplugin install
  polispec` and `rplugin doctor polispec`, all at zero findings, and run the plugin
  for real.
- Guide: `~/.rplugin/docs/guides/writing-a-plugin.md`.
- Native harness controls and the sealed authority plane are polispec-owned domain
  artifacts. Their canonical paths come from the backend capability contract. Back
  up every changed file first, preserve foreign contributions, and require the
  authenticated operator for removal, loosening, managed scope, or protected core
  changes. Native artifacts are not evidence of actual enforcement.
- `native: true` package surfaces are generated by `rplugin package`; do not edit
  the native manifests or hook projections by hand. Keep release metadata in
  agreement, and report missing native or privileged verification explicitly.
- Commands are files: `lib/polispec/commands/*.rb` and `lib/polispec/classify/commands/*.rb`
  are glob-loaded, so a new command or classifier family adds a file and edits no registry.
